The Tevet-7 chat endpoint is the primary way your application talks to the AI agent. You send a plain-English (or French) question, and the agent figures out the right tool — SQL query, document search, or ML forecast — and returns a rich response envelope that includes the answer, the SQL that ran, a chart spec, token accounting, and a complete step-by-step audit trail.

## Endpoint

```
POST /api/chat
```

**Required header:** `Authorization: Bearer <token>`

## Request body

<ParamField body="message" type="string" required>
  Your question in plain language. Maximum 4 000 characters. Examples: "What are my top 5 products by revenue this month?" or "Which items might run out of stock this week?"
</ParamField>

<ParamField body="conversation_id" type="string">
  Pass the `conversation_id` returned by a previous response to continue an existing conversation. The agent loads the message history automatically so you do not need to resend it.
</ParamField>

<ParamField body="history" type="array">
  Explicit conversation context for the LLM. Each item is an object with `role` (`"user"` or `"assistant"`) and `content`. Use this when you manage conversation state on your own side rather than relying on server-side persistence.

  ```json
  [
    { "role": "user",      "content": "What are my top products this month?" },
    { "role": "assistant", "content": "Your top product is Tomates anciennes with €3 200 in revenue." }
  ]
  ```
</ParamField>

<ParamField body="identity_id" type="string" deprecated>
  Caller identity handle (e.g. `"marie"`). Legacy field — ignored when an `Authorization: Bearer` token is present. Identity is read from the JWT in the standard authentication flow.
</ParamField>

<ParamField body="producer_id" type="integer" deprecated>
  Row-level scope value. Legacy field — ignored when an `Authorization: Bearer` token is present. The value is extracted from the JWT in the standard authentication flow. Pass `null` for admin-role requests.
</ParamField>

<ParamField body="role" type="string" deprecated>
  Caller role: `"producer"` or `"admin"`. Legacy field — ignored when an `Authorization: Bearer` token is present. Role is read from the JWT in the standard authentication flow.
</ParamField>

### Example request

```json
{
  "message": "What are my top 5 products by revenue this month?",
  "conversation_id": "conv_abc123"
}
```

## Response fields

Every response is HTTP **200**, including refusals. The shape is always the same — your frontend only needs one success path.

<ResponseField name="answer" type="string">
  The natural-language answer composed by the agent.
</ResponseField>

<ResponseField name="sql" type="string | null">
  The SQL query that was executed against your database, or `null` if no SQL was needed (e.g. a pure RAG question).
</ResponseField>

<ResponseField name="scope_clause" type="string | null">
  The `WHERE` clause that was automatically injected for row-level security (e.g. `producer_id = 42`). Always present for producer-role requests.
</ResponseField>

<ResponseField name="chart" type="object | null">
  A chart specification for data visualisation when the answer contains quantitative results. Fields: `type` (`"bar"` or `"line"`), `labels` (array of strings), `data` (array of numbers).
</ResponseField>

<ResponseField name="tokens_in" type="integer">
  Number of tokens sent to the LLM for this request.
</ResponseField>

<ResponseField name="tokens_out" type="integer">
  Number of tokens generated by the LLM in this response.
</ResponseField>

<ResponseField name="latency_ms" type="integer">
  End-to-end latency measured from the moment the request was received to when the response was serialised, in milliseconds.
</ResponseField>

<ResponseField name="tool_calls" type="array">
  List of tools the agent invoked. Each entry is a string identifying the tool: `"sql_read"`, `"rag_search"`, or `"forecast"`.
</ResponseField>

<ResponseField name="steps" type="array">
  Agent reasoning steps, each with `title`, `detail`, `status`, and `duration_ms`. Useful for building an inspector UI that shows the agent's chain of thought.
</ResponseField>

<ResponseField name="security_checks" type="array">
  Security operations applied during this request — for example, scope injection and table allowlist enforcement.
</ResponseField>

<ResponseField name="refused" type="boolean">
  `true` when the question was out of scope, blocked by guardrails, or the workspace is not yet configured. The `answer` field will contain the reason in plain language.
</ResponseField>

<ResponseField name="tables_touched" type="array">
  List of database table names that were accessed during SQL execution for this request. Empty array when no SQL was executed.
</ResponseField>

<ResponseField name="sources" type="array">
  RAG document sources cited in the answer. Each entry contains `title` and `excerpt` from the matched document chunk.
</ResponseField>

<ResponseField name="ops_analysis" type="object | null">
  Operational copilot analysis object, populated when an ops-level question triggers the ops copilot tool.
</ResponseField>

<ResponseField name="forecast_predictions" type="array | null">
  ML forecasting results when the agent detects a stock-shortage question. Each entry contains `product_name`, `shortage_probability`, and `days_until_shortage`. See [Forecasting](/guides/forecasting) for details.
</ResponseField>

<ResponseField name="trace_id" type="string | null">
  Unique identifier for this request in the observability system. Pass it to `GET /api/traces/{trace_id}` to pull up the full execution detail for that query.
</ResponseField>

<ResponseField name="conversation_id" type="string | null">
  The conversation ID for this exchange. Pass it in your next request to continue the conversation.
</ResponseField>

## Conversation continuity

When you receive a `conversation_id`, pass it back in the next request. The agent retrieves the message history from the server so follow-up questions like "et le mois dernier ?" ("and last month?") are resolved against the original context — no need to resend the full history.

```json
{
  "message": "et le mois dernier ?",
  "conversation_id": "conv_abc123"
}
```

Alternatively, pass an explicit `history` array if you manage state client-side.

## Automatic tool selection

You do not need to specify which tool to use. The agent classifies the intent of every question and routes it automatically:

- **SQL questions** ("top products", "weekly revenue", "net sales") → `sql_read` tool
- **Documentary questions** ("what are the delivery terms?", "where is my CGV?") → `rag_search` tool
- **Forecast questions** ("which products might run out of stock?") → `forecast` tool

## Rate limit

The API allows **120 requests per minute per tenant**. If you exceed this limit the server responds with HTTP `429` and a `Retry-After` header indicating how many seconds to wait before retrying.

<Note>
  A refusal (e.g. a guardrail block or an out-of-scope question) returns **HTTP 200** with `refused: true` — it is not an error status. Your frontend should check the `refused` field rather than relying on the HTTP status code.
</Note>

<Info>
  If the LLM is unavailable or returns an unusable response, the agent automatically falls back to a deterministic rule-based engine so your users always receive an answer.
</Info>
