---
title: "POST /api/auth/login — Authenticate and Get a JWT"
sidebarTitle: "Login"
description: "Verify email and password credentials and receive a short-lived JWT plus a long-lived refresh token, scoped to the user's active tenant membership."
---

Use this endpoint to authenticate an existing user and obtain a JWT access token. The token includes the user's active tenant context — `tenant_id`, `role`, and `producer_id` — so you can immediately call protected endpoints like `/api/chat`. A refresh token is also returned so you can renew the access token silently when it expires, without prompting the user to log in again.

## Request

```
POST /api/auth/login
Content-Type: application/json
```

<ParamField body="email" type="string" required>
  The email address the user registered with.
</ParamField>

<ParamField body="password" type="string" required>
  The user's plaintext password.
</ParamField>

## Response

<ResponseField name="user" type="object">
  The authenticated user record.

  <Expandable title="user fields">
    <ResponseField name="user.id" type="integer">
      Unique numeric identifier for the user.
    </ResponseField>

    <ResponseField name="user.email" type="string">
      The authenticated user's email address.
    </ResponseField>

    <ResponseField name="user.name" type="string">
      The user's display name.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="token" type="string">
  A signed JWT access token valid for 2 hours. Claims include `tenant_id`, `role`, and `producer_id` from the user's active membership. Use this as the Bearer token in subsequent requests.
</ResponseField>

<ResponseField name="refresh_token" type="string">
  A long-lived token you can exchange for a new access token via `POST /api/auth/refresh`. Store this securely — treat it with the same care as a password.
</ResponseField>

## Rate Limit

This endpoint is limited to **5 attempts per minute per IP address** to prevent brute-force attacks. When the limit is exceeded the server responds with `HTTP 429` and a `Retry-After` header:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 43
Content-Type: application/json

{ "detail": "Too many attempts. Retry in 43s." }
```

## Errors

| Code | Cause |
|---|---|
| `401 Unauthorized` | Email not found or password is incorrect. The error message is intentionally generic to prevent user enumeration. |
| `429 Too Many Requests` | More than 5 login attempts from the same IP within 60 seconds. |

## Example

```bash
curl -s -X POST https://your-tevet7-host/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "alice@example.com",
    "password": "supersecret99"
  }'
```

```json
{
  "user": {
    "id": 7,
    "email": "alice@example.com",
    "name": "Alice Martin"
  },
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```
